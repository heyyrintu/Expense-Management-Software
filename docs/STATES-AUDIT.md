# States audit — empty · loading · error · failure toast

**D5.1.** Every route in the app, against the four states every screen owes.
Generated by walking `app/**/page.tsx`, then verified by reading each one.

| Legend | |
|---|---|
| ✅ | Present and purposeful |
| n/a | The state cannot occur on this route (see note) |

## How each column is satisfied

**Empty.** A purposeful `EmptyState` with copy written for someone seeing the
screen for the first time, and **one** action. Routes whose emptiness lives
inside a table use the `DataTable` `empty` slot; routes with several panels
carry a per-panel empty, because "nothing here" about the whole screen tells
a reader nothing about which panel is bare.

Two empties are deliberately NOT offers to create something: `/notifications`
empty is the healthy state, and an empty "Not in bank" bucket on `/bank-recon`
is the goal. Copy says so rather than nudging.

**Loading.** A `loading.tsx` composed from `components/ui/page-skeleton`,
whose pieces are built from the same tokens as the real components —
`PageHeaderSkeleton` mirrors `PageHeader`'s `grid gap-2 pb-6` and its 36px
h1 line box, `TableSkeleton` uses the DataTable's own `h-row`, the ledger
skeleton uses `--ledger-viewport-height`. That is what keeps CLS near zero:
the skeleton and the component read the same numbers, so they cannot drift.

Routes with no `await` in their page need no skeleton and are marked n/a.

**Error.** Next.js error boundaries inherit down the tree, so
`app/(app)/error.tsx` catches every tenant screen and the table records which
file each route actually resolves to. A route gets its OWN boundary only when
the useful recovery differs — on a detail screen it does: "Try again" is right
when a list failed, but when one report won't open the reader's next move is
back to the list. Those routes pass `backHref` to `RouteError` and get both
actions.

D5.1 added boundaries to `(auth)` and `/super`, which had none: a failure
there fell through to `app/global-error.tsx`, an unstyled document — on the
one screen where a stranger forms their first impression of the product.

**Failure toast.** Every failed mutation goes through `notify.failed()`, which
reads `lib/errors.ts` and distinguishes **offline** from a server refusal,
because the advice differs and "try again" while the tunnel is down wastes the
reader's time. A server-supplied message always wins — it knows whether the
period was locked or the report already paid.

Forms report failures **inline** rather than as a toast (the message belongs
beside the fields, and a toast can be missed while looking at the form); those
call sites use `offlineAwareMessage()` so the wording matches.

## Copy voice

Direct, no apologies, no exclamation marks, never blames the reader. Enforced
rather than asserted: `scripts/check-copy-voice.mjs` runs in `npm run lint`
and fails on `!`, "sorry"/"oops", "please try again", "something went wrong",
and second-person blame in any `headline` / `description` / `emptyMessage` /
`title` prop, plus the shared constants in `lib/errors.ts`.

It found one on its first run — `userErrors.unknown` was "Something went
wrong. Please try again.", which names nothing the reader didn't already know
and apologises for it. Now: "That didn't go through. Nothing was changed — try
again." The reader's real question after a failed save is *did I lose it?*,
and every failure line answers that first.

The `/design-system` gallery is exempt: it quotes bad copy deliberately, to
show what the rules are for.

## Known gaps

None outstanding. Two things are worth stating rather than leaving implied:

1. **Skeleton fidelity is structural, not measured.** The primitives read the
   same tokens as the real components, which is why they match — but no
   automated CLS measurement runs in CI. A browser check against a throttled
   connection would be the honest next step, and needs the Chrome tooling this
   session hasn't had.

2. **Offline detection is `navigator.onLine`**, which reports the interface,
   not reachability: a captive portal or a dead upstream reads as online. The
   copy is written so the wrong branch is still true — "Couldn't reach the
   server. Nothing was saved." is accurate either way.
